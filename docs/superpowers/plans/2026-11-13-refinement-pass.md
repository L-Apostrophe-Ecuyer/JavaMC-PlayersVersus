# Refinement pass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Transitions at the most common borders, sub-biomes in forest and plains, a rebalanced dark forest and swamp family, the pale biomes placed, river banks, animals chosen per biome, and the older biomes' features brought up to the newer ones'.

**Architecture:** The biomes are written by the generators (`tools/transition-biomes.py` for the new forest and plains biomes and the pale ones, `tools/wetlands.py` for the wetlands, a new `tools/refine-biomes.py` for the older hand-made biomes, the riverbank features, the variant tags and the wolf variants); `PvBiomeLayout` gets the rules; the riverbank features reach vanilla's biomes through Fabric's biome modifications (`CustomWorldgen`), by two biome tags.

**Tech Stack:** Java 25, Fabric (Minecraft 26.4-snapshot-4), JUnit 5, Fabric game tests, Python 3 generators.

**Spec:** `docs/superpowers/specs/2026-11-13-refinement-pass-design.md`

## Global Constraints

- Vanilla world types keep vanilla's layout (the layout is `PvBiomeSource`'s); `data/minecraft` overrides (wolf variants, tags) only add this mod's biomes.
- Every new biome is in `is_overworld` and `has_structure/mineshaft`, in the tags of what it is (forest, taiga, ...), named in `en_us` and `fr_fr` (as `lemons.add_names` writes), with features in an order every biome agrees on (`BiomeFeatureOrderTest`).
- Generated files are regenerated by the tools, never edited by hand; a tool run must leave unrelated files unchanged.
- Known failures on the base, not ours: `BlightTest.theShakeBeginsBeforeItsFullAndPeaksWhenItIs`, `EndermanShulkerCarrierTest.twoToFourInAHundredCarryAShulker`, the blight game test.
- After a game run: `git checkout logs/latest.log`, `rm -f logs/*.log.gz`.

## Review Focus

- A rule's region cutting a slice it shouldn't (a transition rule taking a whole biome rather than its edge): the partition test, each rule's probes, and the balance test's shares.
- A biome or feature id that doesn't exist (the world fails to load): `BiomeDataTest`, the smoke runs.
- Riverbank features standing away from water, or willows in cold biomes: the game test, the tags.
- Animals that don't fit the place, or variants of the wrong climate: `BiomeDataTest`'s mob checks.
- Feature order cycles from features added to vanilla biomes by modification: the game's own sorter at world load (the smoke runs), `BiomeFeatureOrderTest` for the files.
